Technical Support AI › Live · 24/7 How it works ›
Input Customer calls & texts Phone calls and SMS from customers and field techs, any hour. Twilio SMS routing · ElevenLabs voice agent · platinum customer registry lookup
AI Processing Answers from the knowledge base Understands the question, identifies the product, and pulls the right answer from NBTS documentation and past tickets. Jira RAG Agent · Supabase vector store (match_documents) · parts catalog agent on master_product_list
Output Instant answer + Jira ticket Customer gets a direct answer; a ticket is created automatically for anything needing follow-up. Jira Service Management auto-create · SMS reply branch · call transcript attached
Value 24/7 coverage, 3.7× throughput 265 tickets in June vs. a 5-year average of ~71/month — with ~1,300 tickets through the platform to date.
Ticket lifecycle — every request follows the same path
Intakecall / email / SMS / web form → AI Triagedproduct ID'd, KB answer attached → Assignedrouted to the right engineer → In Progresscustomer & Xylem collaborate on ticket → Resolvedengineer documents resolution → KB Updatedgap closed for next month
The learning loop: monthly export of every ticket shows what AI answered vs. what needed an engineer — those gaps go back into the knowledge base, so the same question gets answered automatically next time.
Submittal Package Generator › Live How it works ›
Input Neptune Benson quote PDF A sales quote — including multi-pool projects and scanned, image-only PDFs. FastAPI on Render · OCR fallback for image-only PDFs
AI Processing Parses & assembles the package Reads the quote line by line, finds every product, and pulls the matching cut sheets and schematics. Quote parser · annotation engine (red row boxes, yellow callouts) · schematic dedup
Output Annotated submittal package A finished, engineer-ready submittal PDF with every quoted item highlighted on its documentation. Merged PDF output · per-item annotation overlays
Value Hours of manual work → minutes Applications engineers spend time on engineering, not document assembly.
Submittal lifecycle — every quote follows the same path
Quote UploadedPDF + job details via the form → Parsedevery line item & model extracted → Docs Matchedcut sheets & schematics per product → Annotatedquoted items highlighted on each page → Deliveredemailed back in ~3-5 minutes → Filed to Jirafull record of every package sent
The tracking loop: the quote and the finished package land on the same Jira ticket, so every submittal that goes out has a complete, searchable record of what was generated and when.
Bid / Spec Scorecard › Live · Scaling How it works ›
Input Project spec document The bid specification for an aquatics or disinfection project. n8n Cloud workflow trigger · document intake
AI Processing Scores 28 categories in parallel Evaluates fit against every scoring category at once, then forms an overall commercial position. Haiku parallel category scoring · Opus commercial position · Supabase scoring registry (multi-product-line)
Output Go / no-go scorecard A structured scorecard with per-category results and a clear recommendation. scorecard_runs + scorecard_category_results tables · full run history
Value Consistent, faster bid decisions Every bid judged by the same yardstick — no more gut-feel triage.
Scorecard lifecycle — every bid follows the same path
Spec Uploadedspec + drawing PDFs via the form → Vision ReadAI reads every page, spec & drawings → Scored28 categories evaluated in parallel → Commercial PositionA/B/C/D win position formed → Deliveredfiled to Jira, copy emailed to you → Registry Updatedrun saved for consistent scoring
The consistency loop: every run and per-category result lands in the Supabase scoring registry, so each bid is judged by the same yardstick and past decisions stay queryable as new product lines come online.

Scaling Across D&A — Proven Playbook, New Teams
The aquatics project becomes the copy-ready baseline for the rest of the division: one landing page, product-specific entry points, and queues routed to each team's first line of support.

What each new product group needs to onboard

  • Product list — which lines the team supports, so entry points and queues can be built per product
  • Point of contact — who receives tickets, for manual or automatic assignment
  • O&M documentation — manuals and technical data sheets to seed the knowledge base (42 products covered today)
  • Copy of the aquatics project — cloned as a starting point; teams test it and flag changes rather than building from scratch
  • Entry point preferences — phone AI, email, SMS, web form, or embedded site widget, all funneling to one Jira project

CRM connection

  • Dynamics 365 — Jira triggers updating Dynamics cases; tested in sandbox, moving to live cases now. Same pattern available for Salesforce (Europe).
